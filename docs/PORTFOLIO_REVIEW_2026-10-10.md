# 作品集前检查 · 2026-10-10

范围：代码审阅、真实解析模块的离线测试、构建、依赖审计、首次安装路径。未在真实 Word 文档中套用格式，未调用付费 AI 接口。

## 已修补

- 修正首次安装顺序：先安装依赖、生成并信任证书，再启动 HTTPS 开发服务。缺少证书时现在明确提示：`缺少本地 HTTPS 证书，请先运行 npm run trust-cert，再运行 npm run dev。`
- 修正密钥与数据流说明：Key 本地保存，调用时连同输入的格式要求发送到配置服务；自定义中转也会收到 Key。不再暗示 Key 不离开本机，也不承诺固定低价。
- API 地址限定为本地 `/llm` 或 HTTPS，拒绝带账号、查询参数或 hash 的地址，不自动跟随重定向；加入 30 秒超时和调用方取消，避免界面永久等待。
- JSON 导入、AI 输出和实际 Word 写入前增加字段类型、数值范围、枚举和页边距校验，拦截负字号、非法对齐与占满整页的边距。
- 修复本地解析器遗漏“小五=9pt”。
- 将仅扫描源码关键词的 smoke 脚本替换为真实模块行为回归。
- 更新兼容范围内的构建传递依赖：nanoid、postcss、source-map-js。

## 展示边界

这是 macOS Word 开发侧载原型，不是 Office 商店产品，也不是可直接访问的在线服务。生产构建本身不提供 `/llm` 代理。真实 Word 中的套用、宿主差异和撤销仍需在文档副本上验收；不要承诺“一键无损修复所有论文格式”。

格式规则没有提及的字段会继承通用模板默认值，用户应先检查预览。通过本地解析可以演示核心思路；AI 解析需要用户自己的服务凭据。
